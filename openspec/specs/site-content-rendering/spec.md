# site-content-rendering Specification

## Purpose
Читалка курса: сборка markdown-контента (план, фазы, шпаргалки) в статический сайт с подсветкой Luau и навигацией между фазами.
## Requirements
### Requirement: Рендеринг контента курса из markdown
Сайт SHALL собираться из существующих markdown-файлов курса (план, фазы, шпаргалки) без изменения их содержимого. Markdown-файлы SHALL располагаться в `src/content/` и регистрироваться как Astro Content Collections.

#### Scenario: Страница фазы отображает гайд
- **WHEN** пользователь открывает страницу фазы (например `/phases/phase-2-killbrick/`)
- **THEN** сайт отображает полный рендер соответствующего md-файла с заголовками, таблицами и списками

#### Scenario: Сборка валидирует контент
- **WHEN** выполняется сборка сайта
- **THEN** Content Collections валидируют все md-файлы, и сборка падает при отсутствии обязательных файлов коллекций

### Requirement: Подсветка кода Luau
Сайт SHALL подсвечивать синтаксис блоков кода Luau в отрендеренном контенте.

#### Scenario: Блок lua-кода подсвечен
- **WHEN** страница содержит блок кода с языком `lua`
- **THEN** код отображается с синтаксической подсветкой

### Requirement: Навигация между страницами
Сайт SHALL предоставлять навигацию: главная страница-дашборд с общим прогрессом, сеткой карточек всех фаз (каждая — ссылкой), блоком ссылок на шпаргалки и ссылкой на полный план; отдельная страница `/plan/` с полным рендером плана обучения; переходы «предыдущая/следующая фаза» на каждой странице фазы.

#### Scenario: Переход к фазе с главной
- **WHEN** пользователь находится на главной странице
- **THEN** отображается сетка карточек всех 10 фаз в порядке следования, каждая — ссылкой на страницу фазы, с индикатором прогресса фазы

#### Scenario: Последовательный обход фаз
- **WHEN** пользователь находится на странице фазы
- **THEN** доступны ссылки на предыдущую и следующую фазу (на первой фазе нет «предыдущей», на последней нет «следующей»)

#### Scenario: Полный план на отдельной странице
- **WHEN** пользователь переходит по ссылке «Полный план» с главной страницы
- **THEN** открывается страница `/plan/` с полным рендером markdown плана обучения

### Requirement: Главная страница без контента плана
Главная страница SHALL быть дашбордом и MUST NOT включать полный рендер markdown плана обучения. Контент плана SHALL отображаться только на странице `/plan/`.

#### Scenario: На главной нет простыни плана
- **WHEN** пользователь открывает главную страницу
- **THEN** видит общий прогресс, карточки фаз, шпаргалки и ссылку на план — без чеклистов шагов из плана

### Requirement: План без дублирующей навигации
Markdown-файл плана обучения MUST NOT содержать дублирующие элементы навигации: inline-ссылки «📘 Подробная инструкция» на страницы фаз и статичную таблицу «Отслеживание прогресса» со статусами ⬜. Навигация к фазам SHALL предоставляться только карточками на главной и ссылками prev/next.

#### Scenario: В плане нет таблицы прогресса
- **WHEN** пользователь открывает страницу `/plan/`
- **THEN** в конце документа нет статичной таблицы «Отслеживание прогресса» и inline-ссылок «📘 Подробная инструкция» перед фазами

### Requirement: Страница плана только для чтения
Чекбоксы шагов на странице `/plan/` SHALL быть неинтерактивными (скрыты). Рядом с заголовком каждой фазы SHALL отображаться статус, вычисленный из реального прогресса соответствующей фазы: «Изучено» (все шаги отмечены), «В процессе N/M» или «Не начата». Первые N пунктов списка фазы в плане (где N — количество отмеченных шагов фазы) SHALL визуально помечаться как пройденные (зелёный маркер, приглушение текста).

#### Scenario: Статус фазы отражает прогресс
- **WHEN** пользователь отметил часть шагов фазы на её странице и открыл `/plan/`
- **THEN** у заголовка этой фазы отображается статус «В процессе N/M», а чекбоксы шагов плана не отображаются и не реагируют на клики

#### Scenario: Пройденные пункты помечены
- **WHEN** по фазе отмечено N шагов (N > 0)
- **THEN** первые N пунктов списка этой фазы на странице `/plan/` отображаются с зелёным маркером и приглушённым цветом текста
