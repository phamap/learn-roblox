## Context

Сайт курса деплоится на GitHub Pages (`https://phamap.github.io/learn-roblox/`) через GitHub Actions. У провайдера автора домен `*.github.io` недоступен без VPN. Решение — зеркало на Cloudflare Pages: бесплатный хостинг статических сайтов с CI, домен `*.pages.dev` доступен из России.

Ключевая техническая особенность: Cloudflare Pages отдаёт сайт только от корня своего домена, тогда как текущий Astro-конфиг жёстко задаёт `base: '/learn-roblox'` (требование GitHub Pages для project pages). Один и тот же билд на обеих площадках работать не будет — base path нужно сделать конфигурируемым.

## Goals / Non-Goals

**Goals:**

- Второй адрес сайта, доступный из РФ без VPN
- Автоматический деплой зеркала при push в `main`, параллельно с GitHub Pages
- Нулевая стоимость, минимум изменений в коде

**Non-Goals:**

- Отказ от GitHub Pages (остаётся основным адресом)
- Синхронизация прогресса между площадками (localStorage разделён по origin; решится на уровне 4)
- Свой домен и CDN-настройки
- Прекрасная скорость сборки/канареечные релизы — берутся как есть

## Decisions

### D1: Cloudflare Pages вместо Netlify/Vercel

Все три дают бесплатный CI + хостинг статики. Cloudflare выбран потому что: `*.pages.dev` стабильно доступен из РФ; щедрые лимиты (500 сборок/мес); та же компания позже даст DNS/доменные услуги, если появится свой домен. Netlify/Vercel — равноценные замены, если Cloudflare не подойдёт.

### D2: Base path через переменную окружения

`astro.config.mjs`: `base = process.env.SITE_BASE ?? '/learn-roblox'`.

- GitHub Actions: переменная не задаётся → работает как сейчас (`/learn-roblox/`)
- Cloudflare Pages: build env `SITE_BASE=/` → сайт от корня

Внутренние ссылки в md-контенте уже относительные (`phases/phase-N-x/`, `./phase-N-x/`, `../../`) — они корректны при любом base. Абсолютных ссылок на base в коде два места (`BaseLayout.homeUrl`, `PhaseLayout.baseUrl`) — оба строятся из `import.meta.env.BASE_URL` и адаптируются автоматически.

Альтернатива — собирать на Cloudflare с тем же `/learn-roblox` и отдавать через redirect-правила — отвергнута: ломаные ссылки, лишние редиректы.

### D3: Подключение репозитория через Git-интеграцию Cloudflare

Cloudflare Pages подключается к GitHub напрямую (GitHub App): push в `main` → Cloudflare сама запускает `npm run build` и публикует `dist/`. Никакого второго workflow-файла и токенов в репо не требуется. Настройка полностью в веб-интерфейсе Cloudflare.

Build settings: command `npm run build`, output `dist`, env `SITE_BASE=/`, `NODE_VERSION=22` (или LTS по умолчанию раннера).

## Risks / Trade-offs

- [Прогресс в localStorage раздельный между площадками] → осознанный компромисс MVP; исчезнет при серверном прогрессе (уровень 4). Задокументировать в README
- [Два источника правды о статусе деплоя] → GitHub Pages остаётся «каноничным» адресом, `.pages.dev` — зеркалом; в README помечено
- [`*.pages.dev` теоретически тоже может попасть под блокировки] → маловероятно; запасной путь — свой домен (~$10/год) поверх той же инфраструктуры
- [Лимит 500 сборок/мес Cloudflare Free] → с запасом превышает потребности личного курса
