## ADDED Requirements

### Requirement: Примеры кода работают при последовательном прохождении
Каждый пример кода в файлах `phases/` SHALL работать без ошибок, если ученик выполняет шаги гайда последовательно в Roblox Studio.

#### Scenario: SlowBrick восстанавливает исходную скорость
- **WHEN** игрок касается SlowBrick и выходит с него через 3 секунды
- **THEN** его WalkSpeed возвращается к значению по умолчанию (16), а не к захардкоженному 8

#### Scenario: PoisonBrick соответствует своему описанию
- **WHEN** в гайде заявлен периодический урон («10 урона каждые 0.5 сек»)
- **THEN** код реализует периодический урон, либо комментарий и неиспользуемые переменные удалены

#### Scenario: Кнопка «Возродиться» имеет серверную реализацию
- **WHEN** игрок умирает и нажимает «Возродиться» после Фазы 5.5
- **THEN** клиент отправляет RemoteEvent, сервер вызывает `LoadCharacter`, игрок возрождается на своём чекпоинте

### Requirement: Комментарии соответствуют поведению кода
Текстовые пояснения в примерах кода SHALL описывать фактическое поведение этого кода, а не предполагаемое.

#### Scenario: Cancel/Play в phase-3 описан корректно
- **WHEN** приведён вызов `tween:Cancel()` или `tween:Play()`
- **THEN** комментарий описывает реальный эффект (отмена анимации / повторный запуск), а не «перемещение в конечную точку»

### Requirement: Чекпоинты используют штатный механизм спавна
Гайд по чекпоинтам (phase-4) SHALL использовать `player.RespawnLocation` для направления респавна игрока, не создавая конкурирующий ручной телепорт из `CharacterAdded`.

#### Scenario: Респавн на последнем чекпоинте
- **WHEN** игрок коснулся Checkpoint2, умер и респавнится
- **THEN** он появляется на Checkpoint2 без конфликта с авто-спавном движка

#### Scenario: Описание поведения движка верно
- **WHEN** гайд объясняет, как Roblox выбирает SpawnLocation при респавне
- **THEN** текст не утверждает выбор «ближайшего» SpawnLocation

### Requirement: leaderstats создаётся ровно одним скриптом
Ровно один серверный скрипт SHALL создавать папку leaderstats; гайд Фазы 6 MUST указывать удалить скрипт из Фазы 5 при внедрении DataStoreManager.

#### Scenario: Отсутствие дубля после Фазы 6
- **WHEN** ученик прошёл Фазу 6 по гайду
- **THEN** в ServerScriptService один источник leaderstats, данные загружаются до создания папки внутри одного PlayerAdded

### Requirement: Звуковые ID уникальны для разных событий
Разные игровые события (смерть, чекпоинт, победа) SHALL использовать различные SoundId либо явно помечаться как временные заглушки; расположение звука (SoundService vs Workspace) MUST совпадать во всех шагах одного гайда.

#### Scenario: Шаги 1.1 и 1.2 phase-7 согласованы
- **WHEN** звук создаётся в шаге 1.1 в SoundService
- **THEN** шаг 1.2 обращается к нему через `game.SoundService`, а не `workspace`
