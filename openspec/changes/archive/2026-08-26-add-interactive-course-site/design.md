## Context

Репозиторий `think` содержит учебный курс по Roblox-разработке в виде markdown-файлов: план (`roblox-learning-plan.md`), 10 гайдов по фазам (`phases/*.md`), две шпаргалки. Внутри файлов — чеклисты шагов в формате GFM task lists (`- [ ]`), блоки кода Luau, таблицы, внутренние ссылки между файлами.

Курс пишет один автор для личного использования; в перспективе — публикация для других. Node.js установлен, аккаунт GitHub есть, репозиторий уже существует и будет перестроен на месте (с сохранением истории через `git mv`). Также в репо живут `.opencode/` и `openspec/` — они не пересекаются с сайтом и остаются без изменений.

## Goals / Non-Goals

**Goals:**

- Статический сайт-читалка курса: план → фазы → шпаргалки, с подсветкой Luau
- Интерактивные чекбоксы шагов с сохранением прогресса в localStorage
- Прогресс-бары на странице плана и в каждой фазе
- Автоматический деплой на GitHub Pages при push (публичный репозиторий, 0₽)
- Точки апгрейда к уровню 3–4 (пошаговый режим, серверный прогресс) без переписывания

**Non-Goals:**

- Аккаунты, сервер, серверный прогресс (уровень 4 — позже)
- Квизы и самопроверки (уровень 3 — позже)
- Пошаговый режим «один шаг за раз» (уровень 3 — позже)
- Переписывание/редактирование контента курса
- Мобильное приложение

## Decisions

### D1: Astro как генератор статических сайтов

**Выбор:** Astro + Content Collections.

**Альтернативы:** VitePress (проще, но жёсткий шаблон документации, меньше свободы для будущего пошагового режима); Next.js (избыточен: сервер и React-веса ради чекбоксов); Docusaurus (тяжеловесен).

Content Collections дают типизированный доступ к md, валидацию при сборке и рендеринг GFM из коробки. Shiki (встроен) подсвечивает Luau без настройки.

### D2: Markdown остаётся единственным источником контента

Контент не переписывается и не мигрирует в JSON. Сайт — производный артефакт, собираемый из тех же файлов. Редактирование курса продолжается как сейчас (md, git diff читабелен). Если когда-нибудь понадобится структурирование — миграция md→JSON тривиальна, обратная — мучительна.

### D3: Vanilla TS вместо UI-фреймворка

Единственная зависимость — `astro`. Интерактивность (чекбоксы, прогресс-бары) — `<script>` внутри `.astro`-файлов + модуль `src/lib/progress.ts` (~40 строк). Astro бандлит такие скрипты с поддержкой TypeScript и импортов. React/Preact не подключаются; если на уровне 3–4 понадобится сложное состояние — решение принимается тогда, точечно.

### D4: Прогресс только в localStorage через единственный модуль

Весь доступ к прогрессу — через `progress.ts`: чтение, toggle, подписка на изменения. Компоненты не знают о хранилище. На уровне 4 реализация внутри модуля меняется на fetch к серверу — компоненты не трогаются.

Данные: ключ `course-progress:v1`, значение — JSON-объект `{ "<stepId>": true }`.

Ограничение принимается осознанно: прогресс привязан к браузеру устройства, не синхронизируется.

### D5: ID шагов = `<slug-файла>:step-<N>`

Например `phase-2-killbrick:step-1`. Slug файла стабилен (латиница уже есть), N — порядковый номер шага в файле. Кириллические якоря заголовков не используются.

Компромисс: вставка шага в середину фазы сбрасывает прогресс последующих шагов этой фазы. Для MVP приемлемо; эскейп-хатч — явные ID у отдельных заголовков, если такая правка случится.

### D6: CI-билд на GitHub Actions, публикация на GitHub Pages

Локально — только `npm run dev` для разработки. Push в основную ветку → Actions собирает сайт (~1 мин) → деплой на Pages. Артефакты сборки (`dist/`) не коммитятся. Требуется публичный репозиторий.

### D7: Переделка существующего репозитория на месте

Файлы переезжают через `git mv`: корневые md → `src/content/{plan,phases,cheatsheets}/`. История git сохраняется. `.opencode/` и `openspec/` не затрагиваются. README переписывается в техническую документацию репозитория.

## Risks / Trade-offs

- [Прогресс сбросится при вставке шага в середину фазы] → задокументировано в D5; при необходимости — явные ID отдельных заголовков
- [Прогресс не переносится между браузерами/устройствами] → осознанное ограничение MVP; путь апгрейда заложен в progress.ts (D4)
- [Контент курса виден в исходниках публичного репо] → принято автором; учебные материалы, это фича
- [Внутренние ссылки между md могут сломаться после переезда] → обновить ссылки при переносе; проверка сборкой (Astro падает на битых ссылках между коллекциями)
- [GitHub Pages кэширует старые страницы] → деплой идемпотентен, кэш протухает за минуты; не критично
