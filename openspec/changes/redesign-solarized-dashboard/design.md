# Design: главная-дашборд + тема Solarized Light

## Context

Сайт — статический Astro-курс (Astro 5, Content Collections, без UI-фреймворков). Сейчас:

- `src/pages/index.astro` рендерит весь план (`roblox-learning-plan.md`) через `<Content />` + добавляет сетку фаз и шпаргалки.
- `src/layouts/BaseLayout.astro` содержит все глобальные стили (GitHub-подобная светлая тема) и клиентский скрипт прогресса.
- `src/lib/progress.ts` — единая точка доступа к localStorage-прогрессу (менять не нужно).
- `PhaseLayout.astro` оборачивает страницу фазы: контент + прогресс-бар + prev/next.

Ограничения: только Solarized **Light** (без тёмной темы и переключателя); шрифт не меняем — работаем жирностью и цветом; чекбоксы на `/plan/` остаются интерактивными через существующий механизм.

## Goals / Non-Goals

**Goals:**

- Главная = дашборд: общий прогресс, карточки фаз, шпаргалки, ссылка на план.
- Отдельная страница `/plan/` с полным планом.
- Палитра Solarized Light на CSS-переменных во всех компонентах.
- Убрать дубли навигации из markdown плана.
- Визуальная «современность» за счёт цвета, жирности, отступов — без новых зависимостей.

**Non-Goals:**

- Тёмная тема / переключатель темы.
- Смена или подключение шрифтов.
- Изменение логики хранения прогресса (`progress.ts`).
- Сайдбар-навигация по фазам (вариант B отклонён).
- Изменение содержимого фаз и шпаргалок.

## Decisions

### D1. Дашборд без `<Content />` на главной

Главная собирается из данных коллекций (`getCollection('phases')`, `getCollection('cheatsheets')`), а не из рендера плана. Полный план — отдельный `src/pages/plan.astro` с `pageSlug={plan.id}`.

*Почему:* простыня на главной была главной жалобой; данные для карточек уже вычисляются (`sortPhases`, `countSteps`). Альтернатива «оставить план на главной под спойлером» отвергнута — всё равно перегруз.

### D2. Общий прогресс считается агрегатом по фазам

На главной: `sum(countDone(slug, total))` по всем фазам против `sum(total)`. Пересчёт при изменении чекбоксов — подпиской через `subscribe()` из `progress.ts`. Чекбоксы самой главной нет, поэтому общий бар обновляется только при возврате с фазы/плана (при загрузке страницы) — этого достаточно.

*Альтернатива:* слушать события между вкладками — YAGNI.

### D3. Карточки фаз с визуальным состоянием

Каждая карточка: номер фазы, название, прогресс «N/M», тонкий прогресс-бар внутри карточки. Состояния: не начата (нейтральная), в процессе (акцент), завершена (зелёная галочка/рамка). Определяется на клиенте из `countDone`.

### D4. Палитра — CSS-переменные в `BaseLayout`

```css
:root {
  --bg:      #fdf6e3; /* base3  — фон страницы */
  --bg-soft: #eee8d5; /* base2  — панели, header, hover */
  --border:  #ddd6c1; /* приглушённый base1 */
  --text:    #586e75; /* base01 — основной текст */
  --heading: #073642; /* base02 — заголовки (жирнее + темнее) */
  --muted:   #93a1a1; /* base1  — вторичный текст */
  --accent:  #268bd2; /* blue   — ссылки */
  --green:   #859900; /* green  — прогресс */
  --cyan:    #2aa198; /* cyan   — hover */
}
```

Иерархия типографики цветом/жирностью: заголовки `--heading` + weight 700–800, текст `--text`, вторичное `--muted`; акценты только синий/зелёный. Подсветку кода (Shiki) приводим к solarized-совместимому виду отдельной проверкой на страницах фаз.

### D5. Чистка markdown плана — руками, один раз

Из `roblox-learning-plan.md` удаляются блоки `> 📘 Подробная инструкция:` и таблица «Отслеживание прогресса». Не генерируем автоматически: файл редактируется редко, автоматизация окупится позже.

### D6. Стили остаются в `<style is:global>` в BaseLayout

Проект маленький, отдельный CSS-файл/переменных не нужен — продолжаем существующий паттерн.

## Risks / Trade-offs

- [Чекбоксы на `/plan/` используют тот же `pageSlug`-механизм] → слаг плана не меняется, идентификаторы шагов стабильны; регрессии быть не должно, но проверить вручную.
- [Shiki-тема подсветки кода может конфликтовать с новой палитрой] → проверить страницы фаз с кодом, при необходимости задать тему в `astro.config.mjs`.
- [Общий прогресс на главной не живой при открытых двух вкладках] → принято как ограничение (D2).
- [Удаление ссылок из плана ломает чьи-то старые закладки/ссылки] → URL страниц фаз и шпаргалок не меняются; риск минимален.

## Open Questions

Нет — все решения приняты пользователем (light-only, вариант A, план отдельной страницей, без смены шрифта).
