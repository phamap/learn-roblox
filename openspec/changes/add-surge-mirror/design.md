## Context

Провайдер автора блокирует домены всех западных статических хостингов. Прямая проверка из сети автора показала: доступен только `surge.sh` (200) из западных сервисов, плюс российские варианты (Яндекс Object Storage — платно, нужна карта). Surge выбран как самый быстрый бесплатный путь; переезд на Яндекс позже возможен поверх той же сборки.

Base path уже параметризован (`SITE_BASE`, см. add-cloudflare-mirror/design.md D2) — код сайта менять не нужно.

## Goals / Non-Goals

**Goals:**

- Адрес сайта, открывающийся без VPN: `learn-roblox.surge.sh`
- Автоматический деплой при push в `main` (без ручных команд)
- Ноль затрат

**Non-Goals:**

- Отказ от GitHub Pages (каноничный адрес)
- Свой домен на Surge
- Яндекс-хранилище (запасной путь, если Surge перестанет устраивать)

## Decisions

### D1: Деплой через GitHub Actions + surge CLI

Workflow `deploy-surge.yml`: checkout → setup-node → `npm ci` → build c `SITE_BASE=/` → `npx surge ./dist --domain learn-roblox.surge.sh`.

Аутентификация CLI — секреты репозитория:
- `SURGE_LOGIN` — email аккаунта
- `SURGE_TOKEN` — токен из `npx surge --token` (получить один раз локально после регистрации)

Альтернатива — деплой вручную с машины (`npx surge dist/`) — отвергнута: забудется; автодеплой обязателен по духу проекта.

Альтернатива — сторонний action (например, yoannfleurydev/marketplace-sursh или actions community surge actions) — отвергнута: лишняя зависимость от третьих лиц, `npx surge` официально поддерживается самим Surge.

### D2: Фиксированный домен learn-roblox.surge.sh

Без явного `--domain` Surge генерирует случайный поддомен при каждом деплое. Фиксированный домен даёт постоянный адрес; первый деплой «застолбит» его за аккаунтом автора.

Риск: домен может быть занят. Если `learn-roblox` занят — выбрать `roblox-obby-course.surge.sh` или подобный (правится в одной строке workflow).

### D3: Параллельный workflow вместо дополнения deploy.yml

Отдельный файл `deploy-surge.yml` рядом с существующим `deploy.yml`. Плюсы: независимые ретраи, читаемость, падение одного не мешает другому. Минус: два запуска Actions на пуш — несущественно (бесплатно для public repo).

## Risks / Trade-offs

- [Surge — маленькая компания, может закрыться] → контент в git не теряется; запасной план — Яндекс Object Storage; переезд = одна строка в workflow
- [Домен learn-roblox может быть занят] → выбрать другой поддомен (D2)
- [SURGE_TOKEN в секретах] → стандартная практика; токен отзывается сменой пароля аккаунта
- [Прогресс localStorage раздельный между github.io и surge.sh] → известный компромисс, задокументировать в README
- [surge.sh теоретически тоже могут заблокировать] → маловероятно сейчас; мониторинг вручную
